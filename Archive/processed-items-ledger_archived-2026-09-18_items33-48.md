## Why this file was split, and the rules that keep it working

On 2026-09-17 this ledger reached **45,720 B** and could no longer be written to at all. `AX-3` recorded a Drive
upload silently truncating somewhere around ~31KB. **That limit was re-tested on 2026-09-18 and no longer exists**
(60,185 B uploaded and verified byte-for-byte; `AX-3` Resolved) — so the split below was not strictly necessary
after all. It stands anyway, on its own merits: a 45,720 B log is unwieldy to read, and rewriting one in full to
append a single row is wasteful and collision-prone.

The split cost nothing and lost nothing, because **a Drive move is metadata-only**. The bytes were never
re-uploaded; the original file object was renamed and moved into `Archive/` exactly as it stood, and a small
successor was created beside it.

**The size rule:** when this file passes **~25KB**, close it the same way — move it to `Archive/` under its dated
split name, and start a fresh live `processed-items-ledger.md` that continues the item numbering and links back
to the previous part.

**The quiet-run rule (added 2026-09-18).** The hourly Hub Drift Watch writes a full ~2KB row every run even when
nothing has changed since the last one — items 38, 39 and 40 were near-verbatim repeats. At that rate this file
crosses the 25KB threshold inside a day, which is churn, not history. **When a run finds no change since the
previous run's row, it writes a single line** naming the date, the run type, and the item number it is unchanged
from — not a restatement of every collection compared. Full detail belongs in the row that first found the drift.

_Scope of that rule, stated plainly because the first version of this paragraph claimed otherwise and the claim
was untrue:_ it **was** applied retrospectively, once, to rows 38, 39 and 40 in the same 2026-09-18 write that
introduced it. Nothing was lost — the full original wording of all three survives verbatim in the archived
predecessor `processed-items-ledger.md (archived 2026-09-18 0550, ...)`, Drive id
`1Qjeo2SqIeCuIavpL3J2GsphGnhei2h__`. Beyond that single pass, **past rows are not rewritten**; the rule governs
new rows only.
